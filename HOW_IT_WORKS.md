# Лабораторная №1

- `permutation.Permute` переносит биты по заданной таблице с выбранным правилом индексации.
- `interfaces` задаёт генерацию ключей, раундовую функцию и блочный шифр.
- `feistel.Network` выполняет раунды: при шифровании (L, R) → (R, L XOR F(R, K)), при расшифровании (L, R) → (R XOR F(L, K), L), ключи в обратном порядке.
- DES: PC-1, сдвиги половин по 28 бит, PC-2 дают 16 ключей по 48 бит. Блок проходит IP, 16 раундов, обмен половин и FP. F выполняет E, XOR, восемь S-блоков и P. Все перестановки выполняются собственной функцией, без lookup.
- DEAL: блок 128 бит, ключ 128/192/256 бит, 6/6/8 раундов. Расписание строится через DES с фиксированным ключом, XOR с предыдущим ключом и константами. Адаптер F создаёт DES с текущим раундовым ключом. До и после сети меняются половины, чтобы F применялась к левой половине.
- Контекст добавляет набивку, применяет режим и при дешифровании удаляет набивку. Режимы: ECB, CBC, PCBC, CFB, OFB, CTR и Random Delta. Набивки: Zeros, ANSI X.923, PKCS7, ISO 10126.
- CTR и Random Delta используют счётчик IV + i × delta по модулю размера блока; delta = 1 для CTR. Random Delta принимает положительный нечётный шаг.
- ECB, CTR, Random Delta и расшифрование CBC/CFB обрабатывают независимые блоки параллельно. Операции возвращают канал результата.
- Файловый API читает файл целиком, использует тот же контекст и записывает результат. Память зависит от размера файла.
- Демо запускается из lab1 командой `go run ./cmd`, показывает работу обоих шифров на байтах и файлах. Для файлов используется PKCS7, поскольку Zeros удаляет исходные конечные нули.

Учебная реализация не предназначена для защиты реальных данных. После удаления оптимизаций демо может выполняться существенно дольше.
